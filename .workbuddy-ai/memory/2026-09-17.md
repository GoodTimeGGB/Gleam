**教训（重要）**：同一文件内**不要并行发多个 Edit**，后写的编辑会基于旧快照覆盖前一个，导致改动静默丢失（本次 config.go、agent.go 各丢失一处）。同文件多处修改必须串行。

## 全平台打包（scripts/package.sh + scripts/make-zip.go）

- 新增 `scripts/package.sh`：构建 5 个平台二进制（Windows CLI / Windows 桌面版 windowsgui / macOS Intel / macOS Apple Silicon / Linux x86_64）→ 同步 latest 无日期命名 → 同步 `website/dist` 官网下载目录 → 打 webui-static / website / release 三个 zip → 归档 pack/ → 生成 SHA256SUMS。
- 新增 `scripts/make-zip.go`（`//go:build ignore`，纯标准库）：支持 `src=alias` 重命名、目录递归、自动设置 0755/0644 权限位（无扩展名或 .exe/.sh 视为可执行），macOS/Linux 解压即跑。系统里没有 `zip` 命令，PowerShell 版本差异也麻烦，所以用 Go 自己打。
- **本机 Go 工具链坑**：交叉编译时偶发 `package xxx is not in std (C:\Go\src\...)`（sort、internal/abi、container/list 等随机包），与代码无关，重试即成功；`go vet ./...` 在本机 GOROOT 下也常报同类错误。脚本因此加了 3 次重试 + `-p 2`，并让 vet 失败不阻断。
- 产物日期标签 20260917，已冒烟验证：打包出的 Windows 二进制启动 Web UI 后 `/api/geo` 正常返回、页面含 GEO 板块。

## 读小米 MiMo-V2.6 训练直播文章后的优化方向（待用户确认是否实施）

文章要点：罗福莉公开训练看板（步数/Token/通过率/评测/费用，约 3.08 万美元每小时）；核心观点是**低价值工具调用 + 反复携带长上下文推高成本，省 Token 的 Harness 要与强模型共同演进**，投入只有转化为"更高成功率、更短流程、更少人工接管"才有价值。

代码核查结论（已确认的差距）：
- `internal/llm/*` 客户端**不解析**响应 usage；`types.GoalResult` 无消耗字段 → 无任务级 token/成本统计（前端只有 ContextView 的上下文窗口估算）。
- 执行器有超时重试但**无重复调用识别**（同 tool+args 重复执行、连续相同失败仍重试）。
- GEO 分析/上下文压缩/反思/摘要这类高频低难度调用与主模型同价，无小模型通道。
- 无 token/调用数预算熔断；成长指标缺成功率、重试率口径。

拟实施方案（优先级）：P0 消耗看板（llm usage → GoalResult.Usage → 前端展示）；P0 低价值调用治理（步骤指纹缓存 + 连续失败短路）；P1 辅助调用走可选 `fast_model`；P1 任务预算熔断（复用审批通道）；P2 指标口径（成功率/重试率 + UI 标注）。
