## 第二轮追加：验收标准（干活的不能兼任验收）

文章里最被强调的一条规则，落地为完整特性。分三步 + 三道闸门：

**三步**
1. 规划阶段定标准：`Planner` 输出 `acceptance`（2–4 条），`normalizeAcceptance` 清洗；拿不到不算错误（向后兼容）
2. 反思阶段逐条判：`Reflector.Acceptance` 非空 → 提示词换成"逐条判定 + criterion 用原文 + note 要具体"，输出 `checks`，并告知"分数由系统算，你不用给分"
3. 分数由系统算：`scoreFromChecks` 按通过比例（全过 100/一半 50/全不过 0）；`alignChecks` 对齐回标准列表，**漏判按未通过计**

**三道闸门（关键：光有判定会被绕过）**
- verdict 说 done 但没全过 → 反射器里降级为 replan
- 循环的完成判定加 `acceptanceSatisfied`——否则 `DoneThreshold` 调低、或模型自称 done 就能绕过（**这是最容易漏的一处**：只在反射器里改不够，agent.go 里 `Score >= DoneThreshold` 的 `||` 分支会兜回来）
- 验收标准**首轮定下就不再改**：重规划没重申则沿用，重申但内容变了也不采纳（承诺不该由没做到的一方改写）

**状态校正**：`applyAcceptanceVerdict` 放在 `finalize` 开头 → 部分通过判 `partial`、一条没过判 `failed`，未达标条目写进 `Error`；只纠正被误判为**成功**的结论，已判失败/取消的不翻案。放 finalize 开头是为了让成长统计/记忆沉淀看到真实状态。

**前端**：任务卡 `renderChecks` 渲染验收清单（对勾/叉/点 + 头部 N/M）；`result.error` 的 callout 标题跟着状态走（partial → "未达标说明"，不再一律叫"失败原因"）。

### 本机新增踩坑（已写进 skill）
- **`pack/CHANGELOG.md` 是 GBK**，仓库其余文件都是 UTF-8。用 Python 按 utf-8 改它会
  `UnicodeDecodeError`，grep 会把它当二进制。**用 Edit/Write 工具改它**（工具按原编码回写，GBK 不破）
- **Python 写 Go 源码要带 `newline=''`**，否则 Windows 下 `\n`→`\r\n`，`gofmt -l` 把整份文件报成未格式化
- **Python 插入的中文里不能用 ASCII 双引号**（会截断 Go 字符串字面量），中文引号用 `「」`
- 固定动作：改完 Go 文件先 `gofmt -l`，有输出就 `gofmt -w`；`gofmt -w` 会保留 CRLF

> **勘误（2026-09-20 核实）**：上面"仓库是 CRLF"是误判。逐文件统计后确认**本仓库全部是 LF**
> （`python -c "raw=open(f,'rb').read(); print(raw.count(b'\r\n'))"` 对所有文件均为 0）。
> 当时 `gofmt -l` 报一片文件，真实原因是**字段对齐列**而非行尾。
> 教训：`gofmt -l` 有输出时先看 `gofmt -d` 的差异内容，别急着归因到行尾。
