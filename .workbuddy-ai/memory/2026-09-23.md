### 缺口不是"没有文档"，是"没有一处能一眼答完"

### 落地时发现的两件事（原计划里没有）

1. **目录名与语义类别不一一对应。** `memory/context.json` 住在 `memory/` 目录下，但它是**会话**状态（滚动上下文与压缩状态），不是跨会话积累。清单按语义归到「会话」并点出这个错位——不点出来的话，读者会按目录名归类，然后得出"删了 `memory/`，会话也一起没了"，而长期记忆与会话上下文其实是两套生命周期。
2. **来源的四类框不住 Gleam 的一类。** 云上多租户里"能力"由平台提供、用户不持有技能文件；Gleam 的**技能与片段**是用户自己攒的，既不是配置（不决定怎么跑）、也不是记忆（不是"发生过什么"）。硬塞进四类里，读者会以为它们与长期记忆同寿、同一种删法。所以单列第五类「资产」，并写明它为什么在四类之外。

配置主文件（`configs/config.yaml`）不在数据目录里——它由 `--config` 指定，默认取**当前目录**下的这个相对路径（`main.go:172`）。所以清单里标 `Outside`、按当前目录解析，并在报告头部写明"换目录跑会显示 `[无]`"。换个目录跑就真的没加载任何配置文件（只剩默认值 + 环境变量），**如实反映**比伪装成"一定在数据目录里"更有用。

## 第二批：文档引用门禁（第 1 层扩展）

### 起因与分界

做上一节的漂移清扫时顺手发现另一种坏法：正文写着「见 §4.6.26」，而那一节要么还没写、要么改了号。Markdown 没有链接检查器管 `§` 这种自造指针，于是**读者跟着指针走到空处不会报错，只会以为"文档里没写"**。

它与「落地进度段」那条**恰好相反**，所以处理方式也相反：

| | 落地进度段 | 文档引用 |
| :-- | :-- | :-- |
| 判什么 | 表头说的和事实一致吗 | 指针指向的东西在不在 |
| 能真失败吗 | 不能（要读懂语义） | 能 |
| 处理 | 约定 + 人工更新 + 写下"为什么不做检查" | **做成闸门** |

**分界就一条：能不能真的失败，且失败是不是即缺陷。** 这条判据值得复用——说不清就别加。

### 落点

新增 `scripts/check-doc-refs.py`：
- 从设计文档抓 `^### (4\.6\.\d+)` 的小节号集合；
- 遍历所有 `.md`（跳过 `.git` / `node_modules` / `dist` / `.workbuddy-ai` / `pack`）找 `§4.6.N`；
- 悬空即打印 `文件:行号 §小节号` 并非零退出；
- **解析不到任何小节时也非零退出**（结构变了而检查还报"通过"，比漏报更坏）；
- `§4.6.N` 这种**泛指**写法不算引用（它说的是"这一片"，不是某一节）。

### 为什么归第 1 层，不新开一层

它本来就是「文本层的格式约定」——gofmt 管**代码文本**、它管**文档文本**，都便宜（<1s）、都不需要编译，按成本序该一起最早撞墙。而**层数一变，"六层"这个说法在 AGENTS.md / README / 设计文档 / 技能里全要跟着改**（先问归属，再谈实现）。所以 `fmt_check` 改名扩展为 `text_layer`，`step` 名字改「格式与引用（gofmt + §ref）」，解释器解析（`python3`/`python`/`py`）提到脚本顶部复用，**找不到 python 时算这一层没过**（静默跳过的检查等于没有检查）。

### 负例控制

把某份清单里一处引用改成不存在的小节号 → **第 1 层 3 秒内失败**、点明 `.\Qoder Cloud Agents 对照与升级清单.md:9`、`PIPESTATUS[0]=1` 立即停止；还原后全仓 99 处引用全部有效。

**一个自我约束**：描述负例控制时**不能写真造的小节号当例子**，否则检查会把这段说明本身判成悬空引用。检查器分不清"举例"与"真引用"——这是对的，写文档时避开即可。（第一次写设计文档时就是这么踩的：写进去才发现，改成"不存在的小节号"。）

### 同步的三处描述

设计文档 §4.6.23 六层表第 1 行 →「格式与引用」+ 新增两段理由（含「但有一类漂移可以机械检查」）；`README` 闸门行与自测节；`AGENTS.md` 命令表行（1946/1950，仍在预算内）。技能 `repo-verify-gate` 同步六层表、第 1 层写法，并新增「克制：不是所有可机械判断的规则都该做成闸门」一节。

### 收尾

## 第三批：环境噪声是「一段窗口」+ 仓库入库

### 证伪「重试一次」

`verify.sh` 又红在第 4 层：首次跑 32 秒失败，**紧接着的重试也失败**，两次命中的还是**不同的** std 包（`internal/stringslite` / `internal/poll` / `internal/syscall/windows`）。

原来的假设是"噪声属于一次调用，立刻重跑就好"——**不成立**。它是一段几十秒的**窗口**，窗口里任何一次 `go` 调用都可能红。而我当时做的正是"重跑一次"，按仓库自己的判据（偶发失败要当**闸门可信度**问题修）这是错的。

**改法**：`go_retry` 由「重试一次」改成「最多 3 次尝试 + 中间等 3 秒」（`GLEAM_GO_FLAKE_ATTEMPTS` / `GLEAM_GO_FLAKE_BACKOFF` 可覆盖）。
- 仍只吃那一个签名 → "多试几次"只可能把**假红变绿**，不可能把真红变绿（真实失败不带这个签名，**一次都不会重试**）。
- 不做无限重试：①环境持续坏下去时闸门要如实红；②每次尝试都是完整跑一层（30–80 秒）。
- 这两个数是**旋钮，不是判据**。

**探针从三段扩到四段**：①噪声一次后成功 → RC=0、调 2 次；②真实失败 → RC=1、**只调 1 次**、且不被误认成噪声；③**噪声两次后成功 → RC=0、调 3 次**（新增，这条才证明"能熬过窗口"）；④噪声一直存在 → RC=1、调 3 次（有上限）。探针自己把等待压到 0。

### 纠正一个自己写错的数字：探针不是「秒级」

`verify.sh` 六层合计 658 秒、总 803 秒，**差额约 145 秒就是探针**。根因：**本机每次进程创建约 2.7 秒**（实测 40 次 `$(cat …)` = 107 秒），而探针全是进程创建。

所以早期文档里「第 0 步自检 `<1s`、所以放在最前面（最便宜的检查最先撞墙）」**两处都错**：它不便宜（比第 1 层的 8 秒贵一个量级），排在最前是因为它是**前置条件**——尺子坏了，后面每层结论都不可信。

已改四处：`verify.sh` 注释、`gonoise.sh` 注释、设计文档 §4.6.23、`docs/known-limits.md` 新增一条（本机进程创建约 2.7 秒/次）。这条也解释了 `smoke.sh` 为什么 443 秒——绝大多数是进程创建。

### 修掉一条时序脆弱的假红测试

全量 `go test ./...` 里 `internal/tools/shell` 红了：`TestShell_ExecExitCode` 报「命令超时（10s）」，跑的是 `cmd /c exit 3`；**单跑该包 3.8 秒就过**。

根因：这条测试用 `New(10 * time.Second)`，10 秒只是**兜底**，与被测行为无关（它断言「退出码怎么报」）。而本机进程创建极慢——`TestShell_OutcomeReportsNonZeroExit` 单跑就要 **10.51 秒**（三条命令，每条约 3.5 秒），正好卡在旧线上。并发跑时就越过 10 秒。

改法：三条与耗时无关的测试改用 `execTimeout = 60s` 常量。**没少测任何东西**——超时行为由 `TestShell_ExecTimeout` 覆盖（显式传 `timeout_sec: 1`），改完仍 1.23 秒通过，这就是负例控制。

## 第六批：按建议批次开发（E / F / G）——把清单从提案变成代码

用户指令只有四个字：「按建议批次开发」。即把第五批清单里的 P0–P3 按建议顺序落地。每批走**同一个固定节奏**：**实现 → 全量测试 → 评测基线对比 → 变异验证 → 文档同步**。这个节奏本身是本批最有复用价值的东西。

### 批次 E（P0）：步骤 panic 的边界

- **为什么必须在子 goroutine 里**：Go 的 `recover()` 只在**同一个 goroutine 的 defer** 里有效。步骤跑在 `go func(i int)` 里，所以在 `eval.Runner` / `cmdGoal` / webui handler 加 recover **全都接不住**——只有 executor 那一处能接，好处是**一处改动覆盖四条执行路径**（eval / goal / webui / 定时任务）。
- **收尾必须留在 guard 之外**：goroutine 里 panic 之后，**defer 之外的剩余语句全部被跳过**。所以 `close(state.finished[i])` / 落盘 / 计数 / 进度这四件收尾事刻意留在 `runStepGuarded` 之外——放进 recover 那段里，依赖这一步的下游会**永远等不到放行**，症状是**任务挂住**，比崩掉更难查。这催生了薄包装 `runStepGuarded`（命名返回值 + `defer recover`）。
- **panic 是「要改代码」，不是「换方案重试」**：新增 `types.ErrInternal` 单列一类，不塞进 `unknown`——归因分布的判据是"能不能回答该先修哪层"。定类**不走 `ClassifyError`**：panic 是执行器自己 recover 到的结构性事实，不需要从文本猜。
- 带栈但压栈：`panicBrief` 前缀 `工具 panic: %v\n`，栈截断到 7 行（完整栈几十行、几 KB，会进 `tasks/*.json` 与 `runs/*.jsonl`）。
- 验证：3 条测试全过（1.4s）；`_mutate_pE.py` **6/6 变异全部会响**。M6（panic 路径不释放下游）跑了 **21 秒**才红——那不是 bug，是设计中的症状被测试自己的 20 秒超时抓成可读失败。

### 批次 F-1（P1）：评测报告回答「这批花了多少」

- **成本代理 vs 成本本体**：`PromptChars` 是代理（提示词多长），token 是本体（实际花了多少）。评测的存在理由之一是"给提示词减法"，减法要算账。
- **不复用 `types.TaskUsage`**：它带 `DurationMs`，而 `CaseResult` 已有 `DurationMS`——两个名字近似、口径不同的耗时同处一个报告必然被拿错。另立 `eval.CaseUsage`，转换点收敛在 `usageFromTask` **一处**。
- **nil 与 0 不是一回事**：`Usage` 用**指针**。select 深度零模型调用 → 用量**缺席**（nil，报告不打印该行）；plan 深度**会**调模型（规划那一次）但调用不经过 `RunGoal`、无 taskID 登记 → **缺口，不是 0**，报告明写「未计量」并说明原因。
- **`--repeat N` 的每一遍都算成本**：重跑真的调了模型、花的是真钱；只报首遍是**账错了，不是省了**。通过率仍取首遍（口径可比），用量取全部遍数。
- 验证：4 条测试全过；full 深度实测打出 `用量：20 次模型调用，30405 token（输入 29755 / 输出 650），10 次工具调用；其中 20 次调用的 token 为估算值`——估算值口径行也生效。

### 批次 F-2（P2）：归档任务不再被报成「不存在」

- **同一事实两个入口给出相反答案 = 静默失效**：`tasks/<id>.json` 在盘上、CLI（`replay.go:294`）读得到，Web UI（`handlers.go:318` 只读内存）回 404「任务不存在」。而且**不像 bug**——404 是明确自信的答复，用户据此认为记录丢了然后重跑、**重复花钱**。

### 收尾时发现的一个新缺陷（本批唯一没在计划里的改动）

### 一条被证伪的核对口径（比上面三处更值得记）

- 上一批写 CHANGELOG 时，我核对的是「**CRLF 计数有没有变**」——813 → 813，看着像"保持"，于是记为通过。
- **这个口径是错的，而且错得刚好相反**：插入 CRLF 文本应该让 CRLF 计数**增加**；计数不变恰恰是"插进去的是 LF"的信号。三引号字符串里的换行是 LF，所以那一次（以及这一次）插入的正文全是裸 LF——两批合计 42 行。
- 复核 HEAD 版本：**纯 CRLF（813 CRLF / 0 裸 LF）**。正确的不变量是「**裸 LF 必须为 0**」，不是"CRLF 计数不变"。
- 修法：`_fixeol.py` 归一化（`replace("\r\n","\n").replace("\n","\r\n")`），并**用"移除插入块后必须与 HEAD 逐字节相同"来证明除行尾外一字未动**。结果：857 CRLF、裸 LF 0、孤立 CR 0、113776 字节。
- 连带两个小坑：①守恒断言的**单位**要跟插入单位一致（插入的是「段落 + 空行」，只减段落会把那个空行算成"额外改动"，断言假红）；②`PREFIX` 不在文件开头（前面还有标题行与空行），用 `len(PREFIX)` 当偏移会切掉开头几行，得到一条与正文无关的假差异——要先 `index(PREFIX)` 定位。

### 明确不做（与第五批一致）

- **行级隔离（坏一行跳过）方向相反**：资料的"行"是**数据**，Gleam 的"批"是**用例集**（版本控制的代码资产）。判据是问它说的那个"一行"在我的语境里是**数据**还是**代码**——是代码/配置就必须整批拒绝，否则把 bug 静默化。
- 通用批量提交接口、闲时调度、`output.jsonl`/`error.jsonl` 分文件、10000 上限、自动断点续跑。

### 风险提示（已写进设计文档）

`gleam eval --depth full` 会**真的调模型、真的执行工具**；在配了非 mock provider 的环境里跑会花钱且有副作用。先确定 provider 再跑。
